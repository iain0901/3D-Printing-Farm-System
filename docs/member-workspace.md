# 3DRFM 會員工作台

會員入口 `/portal/workspace`，沿用獨立 customer token；員工服務入口 `/member-service`，僅 Owner、Admin、Operator 可存取。所有新會員資料以 customerId + workspaceId 授權，不以使用者自行提供的 email 判斷檔案所有權。

## 已接上的流程

- 模型庫：真實 STL 上傳與伺服器格式檢查、尺寸／三角面數、版本、收藏、專案分類、封存／復原、授權下載、3D 預覽。每檔最多 10 MB、200000 面，每會員 100 MB／100 個版本；封存不移除案件所需檔案，因此不釋放容量。
- 雲端草稿：保存原始 STL、變換後 STL、來源變換、擺放、數量、材料、色槽、高度換色與逐面上色。以 SHA-256、三角面數、faceIndex、有效色槽檢查上色資料；重新開啟使用原始 STL 套一次來源變換，避免重複縮放。自動保存需先手動保存並主動開啟；相同幾何／原檔／專案會重用模型版本，修改備註不增加模型容量。revision 避免多視窗覆寫，衝突停止自動保存。
- 製作需求：會員確認風險說明與交付方式後，可將草稿送交專員。案件名稱沿用「臺北日期＋會員＋每日模型序號」。重試同一草稿不重複建立案件；送出後的快照不可改寫，可另存新草稿。此流程是專員報價，不是已執行新機型自動切片。
- 案件詳情：規格、公開進度時間軸、公開報價版本、會員／專員雙向對話、交付與售後申請。沒有回傳內部成本、工作人員備註或存取 token。
- 正式報價：有效且已接受的目前版本才能建立付款訂單；同一案件與版本重試重用訂單。新版／過期報價不能沿用舊付款訂單。
- 帳號：個人、公司／學校／核銷資料、通知偏好、密碼變更、撤銷登入工作階段、帳號刪除申請。變更密碼清除重設 token 並撤銷其他登入；刪除申請由員工確認交易、法定保留事項與實際資料刪除，不假裝自動清除所有交易資料。
- 通知：案件、報價訊息、訂單及服務進度的持久通知與已讀狀態。員工變更會產生會員通知；會員進度頁每 30 秒／視窗取得焦點時更新，設定表單不背景覆寫。已設定 SMTP 時可依偏好寄送 Email；LINE 須設定 Messaging API 且由可信流程綁定 lineUserId。每通知各管道保存發送／失敗狀態並避免同時重複發送；失敗不會假裝成功，也不盲目重試可能已送達的郵件。
- 單據：案件公開報價單列印／下載、已驗證付款紀錄，以及員工上傳已開立的發票／收據 PDF；發票文件不由前端自行編造。電子發票自動開立尚未串接。
- 售後：取消、瑕疵、補印、退款及交付問題申請，最多三張照片；員工回覆與狀態追蹤。申請通過不等於金流已退款，實際取消、退款、補印仍由相應營運流程處理。
- 專案：個人、課程、實驗室、公司零件分類；邀請現有會員並由受邀者接受後取得只讀權限。分享專案模型與案件摘要，不分享會員地址、付款與私人對話；移除成員立即撤銷共用下載權。
- 免費列印：僅清華大學水木書苑，僅單色 PETG 草稿，前端指定名稱 3DSTU_PETG。每會員同時一件進行中申請，保存送出時的模型與設定快照；待人工確認資格／時段，沒有虛構免費額度或自動保留機台。站點完成後標記可取件並發放取件碼，保留歷次處理回覆。不直接操作印表機或加入生產佇列。
- 點數：現有回饋／折抵紀錄、餘額、優惠碼與有效期限；未設定點數到期政策時明示未設定，不捏造失效日期。

## 金流與物流

LINE Pay 已實作 v3 signed payment request 與 server confirm。僅後端已知的訂單、金額與交易編號相符，且 LINE Pay 回覆已確認時寫入 paid，並同步案件付款與歷史。64-bit transactionId 以字串保存。pending／paid 訂單不得變更優惠與點數；重複確認不重複收款或寫入。只允許 LINE HTTPS 付款網址。原本缺 currency 的舊訂單需專員確認新臺幣計價後才能使用正式 LINE Pay。

啟用前須有 `LAYERPILOT_LINEPAY_CHANNEL_ID`、`LAYERPILOT_LINEPAY_CHANNEL_SECRET`、HTTPS `LAYERPILOT_PUBLIC_URL`。先以 `LAYERPILOT_LINEPAY_SANDBOX=true` 完成商店驗收，再開正式環境。測試使用簽章與供應商模擬回覆，未聲稱已完成真實商店收款驗收。街口、PayUni 尚未完成商店協定，維持不可選，即使填入憑證也不回傳假付款成功。

Track.TW 未取得正式 API 協定，維持即時貨態未開放；可用物流單號及官方黑貓、新竹、郵局、交貨便網站查詢。案件交付資料與會員付款訂單同步。新機型自動切片、正式機台規格、多色相容性及自動價格仍待新的後端設定；雲端草稿與專員案件不會冒用免費站點參數產生自動價格。

## API 與資料保存

`api/member-workspace.mjs` 註冊 `/api/customer/workspace/*`：模型、草稿、送出、案件詳情／訊息／付款訂單、專案／邀請、設定／密碼／登入、通知、文件、服務申請、免費列印與回饋。`/api/member-service/*` 提供員工處理與單據、模型授權下載。

新增集合已納入 server COLLECTIONS／TENANT_COLLECTIONS，支援既有 JSON、SQLite、PostgreSQL JSONB 保存與備份／還原；模型與 PDF 使用既有 object storage，可沿用本機或 S3。原始與變換後模型皆為受權限保護的檔案，不在公開網站 URL 暴露。

目前採單一 API 程序內寫入序列及樂觀版本。多 API 程序寫入同一 JSONB 文件前，需沿用部署的單一寫入者，或先增加資料庫交易／版本條件；不能宣稱程序內鎖跨機器有效。

## 驗證

- `npx vitest run api/member-workspace.test.mjs`：權限隔離、模型／上色驗證、去重與版本衝突、案件／客服／文件、專案邀請與撤銷、免費站點、密碼／session、LINE Pay 簽章、64-bit 編號、訂單與案件同步。
- `PLAYWRIGHT_MODULE=… CHROMIUM_PATH=… BASE_URL=http://127.0.0.1:8801 node scripts/check-member-workspace.cjs`：僅本機測試伺服器，真 API ＋正式 build。上傳／WebGL、跨頁還原上色及變換、自動保存容量、會員提交及對話、資料保存、九頁四種寬度、會員與員工的站點申請／取件完整流程。
- 既有 `npm run qc` 與線上上色／切片／會員介面回歸。

提交到 main 不等於已部署到 farmflow.3dstu.com；部署仍需網站主機的實際發布管道。
