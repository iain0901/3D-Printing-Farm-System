# 切片後仍能辨識模型

## 問題與設計依據

使用者回報：準備畫面中的中空圓蓋，切片後變成很小的扁平色塊。
檢查程式與真實引擎確認四個問題：

- 相機使用包含空走、停車與 Z-hop 的總範圍，模型可能被不相關的移動拉遠。
- 所有擠出都只畫成一像素線段，沒有層高、線寬與光照，薄件的立體輪廓難以辨識。
- 超過 100,000 條線段時，舊版只保存前段；後續圖層存在但內容空白，造成模型上半部消失。
- STL 轉成 3MF 時每個三角形都使用獨立頂點，丟失共享邊拓樸。封閉、正體積、每條邊恰有兩面的中空圓環在 OrcaSlicer 被判為空模型；將完全相同座標共用頂點後，同一份幾何可正常切片。現在按物件做精確去重，不四捨五入、不更動面向、孔洞或位置，也不合併不同物件。

## 操作與真實性

- 切片完成預設顯示同一批已變換 STL，保留孔洞、縮放、鏡像及平台位置。不再突然用滿盤細線取代模型。
- 「模型外觀」明確標示為原模型；支撐、平台附著、填充只能到「列印路徑」確認。不能拿原模型冒充成功的實際走線。
- 「列印路徑」預設顯示所有圖層及 100% 線段，空走預設關閉。切換不重設相機。
- 圖層篩選與播放不自動縮放；「顯示全部圖層」停止播放、解除單層、恢復完整範圍及進度，保留使用者的類型篩選。
- 使用 G-code 的 WIDTH / HEIGHT 註解呈現線寬及層高。缺少資料的舊結果使用 0.42 / 0.2 mm 示意厚度並顯示說明，不能當成精密量測工具。
- 原模型保存在此頁工作階段，不新增長期保存個人檔案。重新整理後只剩實際 G-code 時，顯示立體路徑、停用模型按鈕並解釋原因。
- 真實支撐或 raft 若填滿某個位置仍照實顯示，不為美觀刪除引擎產生的內容。原模型孔洞與實際支撐不是同一件事。

## 容量與渲染

`api/toolpath-preview.mjs` 兩次有上限掃描：先統計各層總量和完整擠出範圍，再分配線段預算並在各層均勻取樣。不會只留底部；預設 100,000 條預算高於 3,000 層上限，每層至少保留一筆。超額結果明確標示抽樣，不補畫缺少的路徑。超過行數／層數安全上限仍明確警告僅顯示部分內容。

前端矩形擠出幾何僅沿真實線段建立，Z 為沉積層頂面；沒有用整片面把孔洞封起來。幾何、材質、動畫與 WebGL context 在卸載時釋放。

## 驗證

- `api/toolpath-display.test.mjs`：排除遠端空走範圍、跨 120 層抽樣、完整高度、G-code 線寬／層高、孔洞幾何、橫直視窗取景。
- `scripts/check-toolpath-preview.cjs`：49.7 × 49.7 × 4.5 mm 中空圓環，模型／路徑切換與相機一致、全部圖層、單層、播放、復原完整範圍、320 / 390 px 及重新整理。`REAL_SLICE=1` 使用本機 OrcaSlicer，不控制印表機。
- `scripts/check-slicer-studio.cjs`：既有多模型編輯、實際幾何、專案保存、路徑篩選／播放的回歸檢查。

本機真實 OrcaSlicer 2.4.2 圓環驗證：22 層、17,699 條路徑，包含最後一層；模型與路徑模式皆保留中孔、使用相同相機，320 / 390 px 操作及重新整理後路徑回復通過。這是開發環境結果，不代表已部署至正式站。

最終回歸：40 個測試檔、336 項測試通過；501 個控制情境與 91 種問號說明實際開啟通過；多模型真實切片 180 層、64,664 條路徑，鏡像、縮放、手動位置及專案還原通過。正式建置成功。
